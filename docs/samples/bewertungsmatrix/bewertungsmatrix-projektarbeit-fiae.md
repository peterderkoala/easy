# Bewertungsmatrix Projektarbeit – FI Anwendungsentwicklung

## Meta

- Candidate: `Prüflingsnummer/-name` (blank, filled by examiners)
- Raters: `Erstbewerter`, `Zweitbewerter` (each gives remarks + points per section)
- Sign-off: date + signature of both raters

## Scoring

| Field | Meaning |
|---|---|
| Punkte (0-10) | Raw score per section |
| PunktWert | Score value |
| Gewichtung | Section weight |
| TeilErgebnis | Partial result = points × weight |
| Summe | Sum of partial results (weights total 100 %) |

## Sections

| # | Section | Weight |
|---|---|---|
| 1 | Ausgangssituation | 15 % |
| 2 | Ressourcen- und Ablaufplanung | 10 % |
| 3 | Durchführung und Auftragsbearbeitung | 40 % |
| 4 | Projektergebnisse | 25 % (alt. 20 %) |
| 5 | Gestaltung der Dokumentation | 10 % (alt. 15 %) |

> Sections 4/5 show two weightings (25/10 vs. 20/15). The source does not say when each applies (likely chamber/region-specific). Confirm before use.

## 1. Ausgangssituation (15 %)

Criteria:
- Projektziele und Teilaufgaben, Kundenwünsche
- Projektumfeld, Prozessschnittstellen (Ansprechpartner, Einstieg, Ausstieg)

Rule summary: Documentation must clearly state what the project aims to achieve, its sub-tasks, what the customer wants, and where the project sits in the organization (contacts, inputs, outputs).

## 2. Ressourcen- und Ablaufplanung (10 %)

Criteria:
- Ablaufplanung
- Personal-, Sachmittel-, Terminplanung und ggf. Kostenplanung

Rule summary: Show a workable plan: sequence of steps, people, material/tools, schedule, and costs where applicable.

## 3. Durchführung und Auftragsbearbeitung (40 %)

Criteria:
- Prozessschritte, Vorgehensweise, Qualitätssicherung
- Abweichungen, Anpassungen, Entscheidungen
- Komplexität der Aufgabenstellung

Rule summary: Highest weight. Show how the work was actually done: steps, method, quality assurance, deviations from plan with reasons and decisions, and sufficient task complexity.

## 4. Projektergebnisse (25 %, alt. 20 %)

Criteria:
- Kommentierter Quellcode (if not possible: justification required)
- Soll-Ist-Vergleich (including tests)
- Qualitätskontrolle (maintainability, reusability)
- Abweichungen, Anpassungen
- Benutzerdokumentation (creation, compilation)

Rule summary: Deliver commented source code (or justify its absence), compare target vs. actual incl. tests, assess quality (maintainability, reusability), explain deviations, and provide user documentation.

## 5. Gestaltung der Dokumentation (10 %, alt. 15 %)

Criteria:
- Äußere Form (text, tables, graphics layout)
- Inhaltliche Form (structure, technically correct and standards-compliant presentation)

Rule summary: Document must look clean and consistent, be logically structured, and follow technical conventions and norms.

---

## Agent checklist (self-review of a project documentation)

- [ ] Goals, sub-tasks, customer wishes, contacts, interfaces stated (1)
- [ ] Process, resources, schedule (and costs) planned (2)
- [ ] Method, QA, deviations + decisions, complexity explained (3)
- [ ] Commented code, Soll-Ist incl. tests, quality, user docs present (4)
- [ ] Layout and structure clean, norm-compliant (5)
